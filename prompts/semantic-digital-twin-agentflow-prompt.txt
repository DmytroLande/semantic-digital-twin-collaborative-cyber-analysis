VERSION:
2.0

EXECUTION_MODEL:
AgentFlow structured natural-language pseudocode

PRIMARY_PRINCIPLE:
Agents do not use textual message exchange as the primary
carrier of domain knowledge.

The shared Semantic Digital Twin (SDT) is the common
machine-interpretable analytical state.

Each agent:
READS the current SDT state,
PERFORMS a specialized analytical function,
PROPOSES a structured change,
and the MODERATOR validates the change before it becomes
part of the shared SDT.

# ==========================================================
# 2. GLOBAL OBJECTIVE
# ==========================================================

ROLE:

Construct and iteratively refine a Semantic Digital Twin of
the investigated cyber situation by integrating:

1. the technical network state defined in NETWORK_XML;
2. the dynamic OSINT context contained in OSINT_FILE;
3. the cybersecurity problem defined by THREAT_TOPIC.

The resulting Semantic Digital Twin must serve as:

- a formal model of the investigated cyber situation;
- shared analytical memory;
- a common operational knowledge space;
- a substrate for collaborative multi-agent reasoning;
- a source of traceable attack, attribution, and response
  scenarios.


# ==========================================================
# 3. GLOBAL CONSTRAINTS
# ==========================================================

CONSTRAINT: SOURCE_GROUNDING

OSINT_FILE and NETWORK_XML are the primary factual sources.

Internal LLM knowledge MUST NOT be introduced into the SDT
as factual evidence.

Internal LLM knowledge MAY be used for:

- semantic interpretation;
- entity typing;
- canonicalization;
- candidate-relation generation;
- hypothesis generation;
- contradiction detection;
- reasoning about missing information.


CONSTRAINT: EPISTEMIC_SEPARATION

Always distinguish:

CONFIRMED
SUPPORTED
EXPERT_ASSESSMENT
CLAIM_OF_RESPONSIBILITY
HYPOTHESIS
UNRESOLVED
CONTRADICTED
MISSING_EVIDENCE.


CONSTRAINT: NO_FALSE_NEGATIVES_FROM_ABSENCE

Absence of information MUST NOT automatically be interpreted
as evidence that an entity, relation, or event does not exist.


CONSTRAINT: PRESERVE_ALTERNATIVES

Do not delete alternative hypotheses merely because one
hypothesis currently has stronger support.


CONSTRAINT: PRESERVE_CONTRADICTIONS

Contradictory statements must remain represented in the SDT
until they are resolved or explicitly rejected.


CONSTRAINT: SOURCE_INDEPENDENCE

Repeated publications derived from the same primary
information source MUST NOT be counted as independent
supporting evidence.


CONSTRAINT: TRACEABILITY

Every analytically significant conclusion must permit
reconstruction of:

CONCLUSION
> SEMANTIC_RELATION
> EVIDENCE
> SOURCE.

# 16. MODERATOR TRANSACTION PHASE

TYPE: AGENT

moderator_017

ROLE:
Maintain integrity of the shared Semantic Digital Twin.

STATE:

LOGIC:

FUNCTION ValidateChange(change):

  IF change.sources IS EMPTY
     AND change.provenance != NETWORK_XML
     AND change.epistemic_status == CONFIRMED
  THEN:
      REJECT change

  IF change conflicts with existing confirmed relation THEN:
      SET decision = CONFLICTED
      ADD_CONTRADICTION

  IF change duplicates canonical entity THEN:
      ROUTE_TO entity_analyst_004

  IF change evidence is sufficient THEN:
      ACCEPT change

  ELSE IF analytically plausible THEN:
      SET epistemic_status = HYPOTHESIS
      ACCEPT_AS_HYPOTHESIS

  ELSE:
      REJECT change


FUNCTION ApplyValidatedChanges():

  FOR_EACH STRUCTURED_CHANGESET:

      CALL ValidateChange(change)

      IF decision == ACCEPTED THEN:
          APPLY_TO(GLOBAL_SDT_STATE)

      IF decision == CONFLICTED THEN:
          PRESERVE_BOTH_ALTERNATIVES

      APPEND_TO(AGENT_CHANGELOG)

FUNCTION ForwardExpansion():

  INITIAL_FRONTIER = {
      relevant_network_assets,
      THREAT_TOPIC,
      confirmed_events,
      supported_vulnerabilities
  }

  LABEL(FORWARD_LOOP)

  FOR_EACH entity IN INITIAL_FRONTIER:

      FIND semantically and evidentially supported successors

      PROPOSE new nodes and relations

      MARK provenance = F

  IF meaningful_new_elements_found
     AND expansion_limit_not_reached
  THEN:
      UPDATE INITIAL_FRONTIER
      GOTO(FORWARD_LOOP)

  RETURN G_F

# ==========================================================
# 19. BACKWARD SEMANTIC EXPANSION
# ==========================================================

TYPE: AGENT

ID:
backward_expander_010

ROLE:
Independently reconstruct conditions required to support
each analytical hypothesis.

STATE:

G_B = {}

LOGIC:

FUNCTION BackwardExpansion(hypothesis):

  START_FROM hypothesis

  LABEL(BACKWARD_LOOP)

  ASK:
  "What facts, conditions, entities, and relations should
   exist or be observable if this hypothesis were correct?"

  EXTRACT required_preconditions

  FOR_EACH precondition:

      SEARCH RELEVANT_OSINT_CONTEXT

      IF observed THEN:
          ADD relation
          MARK provenance = B

      ELSE:
          ADD_INFORMATION_GAP

  IF additional_required_preconditions_exist
     AND expansion_limit_not_reached
  THEN:
      GOTO(BACKWARD_LOOP)

  RETURN G_B


LOGIC:

START_PARALLEL(
    BackwardExpansion(H_1),
    BackwardExpansion(H_2),
    ...,
    BackwardExpansion(H_n)
)

MERGE_RESULTS(to semantic_aligner_011)

# 20. SEMANTIC ALIGNMENT AGENT

TYPE: AGENT

ID:
semantic_aligner_011

ROLE:
Align fact-driven and hypothesis-driven semantic subgraphs.

STATE:

LOGIC:

FUNCTION Align(G_F, G_B):

  FOR_EACH node_f IN G_F:

      FOR_EACH node_b IN G_B:

          CALCULATE semantic_correspondence

          IF correspondence >= SEMANTIC_MATCH_THRESHOLD THEN:
              MARK_AS_MATCH

  COMPARE:
      entity identity
      relation type
      temporal consistency
      source support
      TTP equivalence
      infrastructure overlap
      campaign overlap

  ASSIGN provenance:

      F
      B
      FB

  IDENTIFY:
      mutual_support
      missing_expected_evidence
      conflicting_evidence
      alternative_explanations

  RETURN SEMANTIC_ALIGNMENT_CHANGESET

FUNCTION DetectContradictions(G*):

  FOR_EACH relevant relation pair:

      CHECK:
          semantic_conflict
          temporal_conflict
          identity_conflict
          attribution_conflict
          source_conflict

# ==========================================================
# 22. SCENARIO ANALYST
# ==========================================================

TYPE: AGENT

ID:
scenario_analyst_013

ROLE:
Extract scenarios from the Semantic Digital Twin rather than
generate them freely as narrative text.

STATE:

attack_scenarios = {}
attribution_scenarios = {}
response_scenarios = {}

FUNCTION IsAdmissibleScenario(P):

  RETURN (
      semantic_consistency(P)
      AND temporal_consistency(P)
      AND evidential_support(P)
      AND no_unresolved_critical_logical_contradiction(P)
  )


FUNCTION ExtractScenarios(G*):

  FIND candidate paths and connected subgraphs

  FOR_EACH candidate P:

      IF IsAdmissibleScenario(P) THEN:

          CLASSIFY P AS:
              ATTACK
              ATTRIBUTION
              RESPONSE

          CREATE:

              scenario_id
              scenario_type
              ordered_nodes
              ordered_edges
              initial_state
              final_state
              evidence
              source_clusters
              contradictions
              missing_evidence
              confidence
              status

      ELSE:
          REJECT_AS_SCENARIO
          PRESERVE_AS_CANDIDATE_IF_ANALYTICALLY_RELEVANT

  LIMIT results to MAX_SCENARIOS_PER_TYPE

  RETURN STRUCTURED_CHANGESET

FUNCTION AnalyzeAttribution():

  IDENTIFY candidate ThreatActors

  FOR_EACH candidate_actor:

      EXTRACT all relevant paths:

          Incident
          > observable evidence
          > TTP
          > Tool/Malware
          > Infrastructure
          > Campaign
          > ThreatActor

      NOTE:
      This sequence is illustrative, not mandatory.

      USE only relations actually represented in G*.

      SEPARATE:

          confirmed_facts
          supporting_evidence
          independent_source_clusters
          expert_assessments
          claims_of_responsibility
          indirect_indicators
          contradictory_evidence
          missing_evidence

      DO NOT calculate attribution merely by counting mentions.

      DO NOT treat TTP similarity alone as sufficient evidence.

      CALCULATE attribution_confidence

      CREATE attribution_profile

  RETURN ATTRIBUTION_RESULTS


# ==========================================================
# 24. DEANONYMIZATION ANALYST
# ==========================================================

TYPE: AGENT

ID:
deanonymization_analyst_015

ROLE:
Perform controlled escalation of actor identification only
when supported by evidence.

STATE:

identification_levels = {}

LOGIC:

FUNCTION ControlledDeanonymization(actor):

  IF ALLOW_DEANONYMIZATION == FALSE THEN:
      RETURN NOT_EXECUTED

  LEVEL_0:
      unidentified_actor

  LEVEL_1:
      alias_or_threat_group

  LEVEL_2:
      organization_or_affiliation

  LEVEL_3:
      identified_person

  FOR level FROM 0 TO 2:

      IF new_independent_evidence_supports(level + 1)
         AND no_critical_unresolved_contradiction
      THEN:
          ADVANCE_TO(level + 1)

      ELSE:
          STOP

  IF final_level == LEVEL_3 THEN:

      SET status = REQUIRES_HUMAN_REVIEW

  RETURN DEANONYMIZATION_RESULT

FUNCTION CheckConvergence():

  DEFINE:

      new_nodes =
      count(nodes added during current iteration)

      new_edges =
      count(edges added during current iteration)

      unresolved_critical_contradictions =
      count(critical contradictions)

      high_priority_gaps =
      count(high priority information gaps)

      major_hypothesis_changes =
      count(material changes in top hypotheses)

  IF new_nodes == 0
     AND new_edges == 0
     AND major_hypothesis_changes == 0
  THEN:
      SET CONVERGENCE_STATUS = TRUE

  ELSE:
      SET CONVERGENCE_STATUS = FALSE


CALL CheckConvergence()


IF CONVERGENCE_STATUS == FALSE
AND ITERATION_NUMBER < MAX_ITERATIONS
AND new_relevant_information_available
THEN:
    GOTO(ITERATION_START)


IF ITERATION_NUMBER >= MAX_ITERATIONS THEN:
    GOTO(FINAL_VALIDATION)


IF CONVERGENCE_STATUS == TRUE THEN:
    GOTO(FINAL_VALIDATION)
