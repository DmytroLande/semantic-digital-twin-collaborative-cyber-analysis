# ==========================================================
# MULTI-AGENT TEXTUAL COLLABORATION PROMPT
# Cyber Threat Analysis of a Corporate Network
# Experimental Mode B
# Version 1.0
# ==========================================================

TYPE: SWARM

NAME:
multi_agent_textual_cyber_threat_analysis

VERSION:
1.0

EXECUTION_MODEL:
Specialized multi-agent analysis with textual collaboration

PRIMARY_PRINCIPLE:

Specialized agents independently analyze different aspects
of the same cybersecurity problem.

Agents communicate analytical knowledge ONLY through
textual reports.

There is NO shared Semantic Digital Twin.

There is NO persistent shared graph of entities and relations.

There is NO structured transaction mechanism for modifying
a common machine-interpretable analytical state.

The MODERATOR receives textual outputs from specialized
agents and synthesizes the final analytical result.


# ==========================================================
# 1. INPUT PARAMETERS
# ==========================================================

PARAMETERS:

OSINT_FILE =
"{name of the file obtained from the InfoStream system}"

NETWORK_XML =
"{name of the XML file containing the network description}"

THREAT_TOPIC =
"social engineering through email messages"


# ==========================================================
# 2. GLOBAL OBJECTIVE
# ==========================================================

Analyze the corporate network described in NETWORK_XML
using the factual information contained in OSINT_FILE.

Investigate the cybersecurity problem defined by
THREAT_TOPIC.

The analysis must identify:

- relevant network assets;
- possible initial compromise mechanisms;
- relevant vulnerabilities and weaknesses;
- tactics, techniques, and procedures (TTPs);
- credential-access mechanisms;
- privilege-escalation mechanisms;
- lateral-movement mechanisms;
- tools and malware;
- possible attack scenarios;
- possible attribution scenarios;
- possible response scenarios;
- contradictions;
- information gaps;
- source support for significant analytical conclusions.

The initial analytical condition is:

A user workstation may be compromised through email-based
social engineering.

Determine possible subsequent developments of the attack
using only NETWORK_XML and OSINT_FILE.

Do NOT assume in advance which internal asset becomes
the final target.


# ==========================================================
# 3. EXPERIMENTAL RESTRICTION
# ==========================================================

IMPORTANT:

This is MULTI-AGENT TEXTUAL COLLABORATION MODE.

Use specialized analytical agents.

Each agent independently analyzes its assigned aspect
of the problem.

Each agent returns a TEXTUAL ANALYTICAL REPORT.

Agents MAY read:

NETWORK_XML
OSINT_FILE
THREAT_TOPIC

Agents MAY receive textual reports produced by other agents
when explicitly specified by the workflow.

Agents MUST NOT:

- create a shared Semantic Digital Twin;
- maintain a shared knowledge graph;
- directly modify a common graph;
- use structured change transactions;
- use ADD_NODE / ADD_EDGE operations on shared state;
- maintain persistent shared entity or relation registries;
- use a common machine-interpretable analytical state.

Knowledge transfer between agents must occur through
TEXTUAL REPORTS.

The MODERATOR must synthesize the final result from those
reports.


# ==========================================================
# 4. SOURCE GROUNDING
# ==========================================================

NETWORK_XML and OSINT_FILE are the only factual sources.

Internal LLM knowledge MUST NOT be introduced as factual
evidence.

Internal model knowledge MAY be used for:

- semantic interpretation;
- entity typing;
- canonicalization;
- interpretation of cybersecurity terminology;
- hypothesis generation;
- contradiction detection;
- interpretation of relations.

Every agent must distinguish:

CONFIRMED
SUPPORTED
EXPERT_ASSESSMENT
CLAIM_OF_RESPONSIBILITY
HYPOTHESIS
UNRESOLVED
CONTRADICTED
MISSING_EVIDENCE.

If evidence is insufficient, explicitly return:

INSUFFICIENT_EVIDENCE.
